## 四、执行顺序总览

建议按 6 个批次推进。

## Batch 1：项目骨架与主闭环

目标：跑通最小客户端主闭环。

范围：
- 主工程初始化
- 模块骨架搭建
- Today / Prayer / Completion 页面
- 本地静态内容读取
- 基础用户状态（提醒时间、streak、完成记录）

产出：
- 可运行 demo
- 客户端主模块骨架
- MVP 第一次可见版本

## Batch 2：内容引擎与离线缓存

目标：让 today 内容可调度、可缓存、可离线回退。

范围：
- 内容包结构
- content-engine
- offline-cache
- 默认内容包
- 7/30 天缓存与回退顺序

产出：
- 内容读取链路稳定
- 弱网/无网仍可打开 today

## Batch 3：推送系统

目标：完成重推送核心能力。

范围：
- 远程推送
- 本地推送兜底
- 推送时间配置
- 去重逻辑
- 推送事件埋点

产出：
- 每日推送链路可跑
- push -> open -> prayer -> completion 数据闭环

## Batch 4：配置化与四壳分化

目标：让一套内核支撑 4 个 app。

范围：
- config-runtime
- 主题包
- content pack
- push pack
- women mode 差异
- 4 个 app shell

产出：
- 四个 flavor / target 可独立运行

## Batch 5：后台与内容运营能力

目标：让内容和推送可持续运营。

范围：
- 内容 CMS
- 推送配置后台
- 内容发布接口
- 内容版本管理
- campaign 管理

产出：
- 运营可更新内容与推送，不依赖发版

## Batch 6：商业化与优化

目标：补广告规则、埋点、A/B、上架准备。

范围：
- ad-policy
- analytics
- frequency control
- experiment hooks
- 商店素材配套

产出：
- 第一阶段可商业化版本
