## 一、使用规则

这份文档用于做 4 件事：
- 统一记录 5 条主线的待办
- 标注优先级
- 后续按轮转方式持续优化
- 允许随着实际开发进展动态调整优先级

### 优先级定义
- `P0`：当前不做会阻塞整体推进
- `P1`：高价值、应尽快完成
- `P2`：重要但可排后
- `P3`：优化项/扩展项

### 优先级分类
- `阻塞型`：不完成就卡后续主线
- `内容型`：直接决定内容池、编排、推送、文案质量
- `研发型`：决定本地数据、接口、seed、运行链路是否可落地
- `验证型`：决定内容源、推送、离线、E2E 是否可靠
- `增长型`：决定 ASO、商店转化、数据反馈闭环
- `设计型`：决定页面表达、模式差异、节日态能否落图

### 动态调优先级规则
出现以下情况时，允许直接调整优先级：
- 某条线成为新的阻塞项
- 某个待办已被上游文档/设计/研发结果提前依赖
- 某项工作已完成，后续关联项自然前移
- 节日 / Women Mode / 推送 / 广告 / 数据等高敏模块出现新约束

调整要求：
- 直接在本文件更新优先级
- 如有明显变化，同步更新相关文档
- 重要变化同步写入项目 memory
